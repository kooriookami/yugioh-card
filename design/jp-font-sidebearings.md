# 日文字体留白排版方案

- 状态：已实施并完成第 13 节记录的验证；按后续反馈改用动态字体信息。
- 日期：2026-11-16，初稿为 2026-11-15。
- 基线：`master`，`583281f119aacbf763a4ff49737ff81065bd820a`。
- 分支：`codex/jp-font-spacing`，使用现有 checkout。

## 1. 要解决的问题

旧 `ygo-jp` 把一部分字符的留白调整直接写进了字体。更换字体后，这些规则不容易复用，也不能在排版时独立调整。

本次建议使用已经恢复占宽的新字体，把留白处理移到 `CompressText`：保留字形本身，只改变字符的逻辑占宽和绘制位置。测量、换行、压缩、对齐、注音定位和导出使用同一份布局结果。

这是自定义的比例留白处理，不等于字体原生的 OpenType `palt`。不通过 `scaleX` 压扁字形来模拟去留白；现有容器宽高不足时的横向压缩仍按原规则执行。

## 3. 哪些字符处理

处理范围为：**全体汉字、假名及明确列出的额外字符**。实际排版时还需确认字符由当前 `ygo-jp` 覆盖，不处理 fallback 字体中的字形。范围按字符类别定义，不以固定的 6900 字符名单作为边界。

额外字符目前包括 `々〆゛゜ゝゞー`。其中部分也属于假名类别，匹配时按并集去重，不重复处理；后续需要增加其他符号时明确列出，不扩大到整个标点区块。

长音符 `ー`（U+30FC）明确参与缩减，按当前字体的实际占宽和左右留白应用同一个 `sideBearingRatio`，不先强制恢复为 1024，也不改变字形。它不计入下表 6900 个已恢复字符的统计，缩减后相对旧版的排版差异单独核对。

当前字体已恢复并核对的字符统计如下。这是本版字体的基线记录，不是处理范围的数量上限：

| 类别 | 当前恢复字符数 | 默认规则 |
| --- | ---: | --- |
| 汉字，含兼容汉字 | 6725 | 两侧各保留 50% |
| 平假名及其标记 | 87 | 两侧各保留 50% |
| 片假名 | 86 | 两侧各保留 50% |
| `々〆` | 2 | 两侧各保留 50% |
| 合计 | 6900 | 当前已核对的恢复字符基线 |

不处理以下字符：

- 全角、半角数字，以及全角、半角拉丁字母。
- 希腊字母、西里尔字母。
- 未列入额外字符集合的标点和符号，例如 `。、「」【】（）！？・`。
- 半角空格、全角空格、制表符和换行控制符。
- 新字体没有覆盖、依赖其他字体 fallback 的字符。

使用明确的汉字、平假名和片假名分类，补充上述额外字符，不能把整个“CJK 区块”或“全角字符”都纳入。`々` 的 Script 为 Han，而 `〆` 和不少标点为 Common；全角数字虽然位于全角形式区块，也明确排除。

运行时从实际加载的字体读取字符映射和字体单位，按字符类别、额外字符集合和字体自身的覆盖范围共同判断。不预写覆盖表、字宽或字体指纹，不固定字符数量，也不把功能绑定到 `ygo-jp`。更换字体或补充字符后，直接读取该字体的信息，无需重新生成配置文件。

## 4. 动态字体信息与留白计算

### 4.1 度量来源

新增共享的 `font-info.js`，使用 `fontkit/core`，只注册 TTF/OTF、WOFF、WOFF2 格式解析器。浏览器与 Node 使用同一份字体信息和计算代码；排版、绘制与导出仍由 Leafer 完成，不把字形改为自绘路径。

浏览器加载器获取字体二进制，将同一份数据传给 `FontFace` 并保存于字体加载记录，不重复下载。Node 同步注册字体并保存文件数据，维持原有同步预览与 `ready` 流程。字体解析器只在首次需要留白处理时解析该加载记录。

按需读取 `unitsPerEm`、字符映射、字形的 `advanceWidth` 和 `bbox`，不假定所有字体均为 1024 单位。只有文本实际用到的待处理字符才读取字形边界，不在加载时遍历全字体。

采用加载字体的 Regular 度量，不因描边、阴影或合成粗体的墨迹扩大而改变留白。实际文字仍使用调用方指定的粗体、颜色、描边等样式。

初稿曾考虑 Canvas `TextMetrics`。实测浏览器与 Node 对「日」的右边界分别返回 784 和 779，在 38px 下会造成约 0.07px 的调整后占宽差异。因此实现改为读取实际字体中的字形边界，统一浏览器和 Node 的留白计算，不再依赖 Canvas 墨迹边界。

`Text.getBounds('content', 'inner')` 继续用于原生文字段的正常测量，但不能用它获得左右留白。在本项目当前后端中，它返回的是内容占宽，不是字形墨迹边界。

### 4.2 左右留白

设 `glyph` 为实际字体覆盖的单码点字形：

```text
A = glyph.advanceWidth                  // 原始前进宽度
L = glyph.bbox.minX                      // 左留白
R = A - glyph.bbox.maxX                  // 右留白
I = glyph.bbox.maxX - glyph.bbox.minX     // 可见字面宽度
```

只在字体已经加载、字符符合第 3 节的类别规则且被字体覆盖、度量均有限且可靠时采用结果。误差不超过 0.01 单位时归一化到最近整数；其他有限的小数正常计算，不要求字体度量接近本版日文字体。

空白字符或无墨迹结果不做裁边。遇到负侧边距时保留该侧原值，不把字形外伸误当成可裁掉的空白。计算结果非有限数或占宽非正时，回退到原生度量，避免文字消失。

### 4.3 比例留白规则

设留白保留比例为 `r`，只使用内部参数 `sideBearingRatio`。通用文字路径默认为 `1`，沿用字体原始度量；本次接入的日文样式设为 `0.5`。汉字、假名和明确列出的额外字符使用相同公式，不另外补白。

```text
L' = min(L, ceil(L × r))                 // 仅对正留白；负值保留
R' = min(R, ceil(R × r))
A' = A + (L' - L) + (R' - R)
```

向上取整发生在字体自身的设计单位，不是在最终像素上取整，保留旧字体逐侧取整的约定。`min` 防止小数边距因取整反而增加留白；本次只减不加。负侧边距按上一节的规则保留。`r = 1` 时直接使用原生文字路径，无需读取字形边界或取整。

实际排版字号为 `f = 当前字号档位 × fontScale`，字体单位为 `U = unitsPerEm`：

```text
逻辑占宽 = A' × f / U
字形水平位移 = (L' - L) × f / U
```

以「日」为例：`A=1024, I=523, L=256, R=245`。`r = 0.5` 时得到 `L'=128, R'=123, A'=774`。「あ」得到 `A'=861`。全角「０」不进入该规则，沿用供体的 702 占宽。

旧字体的汉字实测规律是每侧保留 50% 后再加 30 字体单位，例如「日」的占宽为 834；这只是历史度量，不是 `palt` 标准。本草案不再保留额外补白，因此 6725 个汉字各比旧字体少 60 单位占宽，在 38px 字号下约为 2.23px；这可能改变换行和压缩结果，需要结合实卡校准。其余 175 个恢复字符仍符合原来的 50% 留白规则。

### 4.4 已做的可行性检查

以下是前期使用实际字体与依赖完成的基线核验，实际实现的验证结果见第 13 节：

| 检查 | 结果 |
| --- | --- |
| 反算旧字体的处理规律：汉字每侧 `ceil(L/R × 0.5 + 30)`，其余恢复字符每侧 `ceil(L/R × 0.5)` | 6900 个字符的占宽和左边距全部与旧 `ygo-jp` 精确一致；这是历史规律的核验，不是本草案的默认公式 |
| 新字体全部 7669 个字形的 CFF 占宽与 `hmtx` | 一致 |

## 5. 接入现有布局

### 5.1 正文段适配器

保留现有分词、ruby 标记与换行层次，在一个正文 item 内增加“正文段适配器”：

- 不符合处理类别或未被当前字体覆盖时，继续使用单个原生 Leafer `Text`。
- 命中时，以 Leafer `Group` 承载需要单独定位的字符和原生文字段。Group 的位置是逻辑起点，子 Text 才应用字形水平位移。
- 不需要处理的连续文本保留为完整 Text 段，避免额外拆散西文连字、组合字符和其他文字系统的塑形。
- 内部切分以字素簇为边界。多码点组合、变体选择符等没有对应规则时，整个字素簇走原生路径，不拆开逐码点裁边，也不改写输入文本。
- 有注音的 item 仍是原来的布局原子；内部字形定位不改变外层换行和 ruby 配对关系。

适配器明确提供自然占宽、调整后占宽、墨迹偏移、样式更新和销毁操作。不要把 `rubyLeaf` 从 Text 换成 Group 后继续直接写 `fontSize`、`fill` 等属性；这些更新必须传递给内部 Text。

### 5.2 宽度和绘制位置使用同一记录

`createRubyLeaf()` 产生的 `originalWidth` / `normalWidth` 改为调整后的自然占宽。超长切段、首行压缩、高度二分、行尾空格清理、对齐和 `bounds.width` 都使用它。

不得只改绘制 x、仍以 1024 全角宽度换行；也不得仅缩小逻辑宽度、仍让字形停在原来的左留白位置。

Group 的原生内容包围盒可能包含子 Text 原有的空白，不能据此重新计算逻辑占宽。布局使用适配器的 advance；墨迹和描边越界另行保留，避免导出或命中区域误裁切。

### 5.3 字距、缩放与注音

1. 字形留白先计算，再叠加现有 `letterSpacing` 和 `wordSpacing`，最后进入已有横向压缩。
2. 自行定位的子 Text 使用零字距，布局层只加一次字距；原生文字段继续使用 Leafer 的正常测量。保留当前末字符也计入一次字距的约定，本次不修改字距语义。
3. 现有 `updateRubyScale()` 缩放外层正文段，内部位置和逻辑宽度一起缩放，不重复缩放留白。
4. `fontScale`、正常/小字字号按同一个参考单位重新计算，不在已经缩放的数据上累计乘比例。保持 #32 的有限搜索与小字回退规则。
5. 注音 `rt` 使用原来的 `ygo-tip`，不启用本规则。注音居中、扩宽 padding、二次重排以正文段的逻辑起点和调整后宽度计算，不读取第一个子字形的偏移坐标作为起点。
6. 粗体、描边、阴影和渐变传递给内部 Text。多字符正文段的渐变使用共同的段坐标，不能因拆成多个子 Text 而每个字重新起一个渐变。

## 6. 内部参数与启用范围

`CompressText` 只增加一个内部标量参数，不增加独立开关或汉字补白参数。标量继续适用现有 `Object.is` 更新判断：

```js
{
  sideBearingRatio: 1, // 内部默认值：沿用字体原有度量；目标日文样式设为 0.5
}
```

字体身份、加载状态、字符类别、额外字符集合和字体覆盖由内部判断，不作为额外参数。比例小于 1 时，对实际加载字体覆盖且符合第 3 节范围的字符调整留白。不限制字体名称、指纹或字框单位；未取得实际字体数据时保留原生路径。比例为 1 时不读取字形边界。

`sideBearingRatio` 有限时限定到 `[0,1]`：`0` 去掉可处理的正留白，`0.5` 保留一半，`1` 使用原始度量。缺省或无效值使用 1，不产生零宽文字。布局与测量只读取这一个比例值。

该参数只由项目内部样式与绘制流程传递。用户不需要知道、设置或保存它；不增加编辑界面开关、卡片 JSON 字段、公共类型字段或面向用户的参数文档，也不把开放用户控制作为本次计划。

接入 OCG 和第二期卡片的日文样式，包括卡名、魔法/陷阱类型、种族、效果与灵摆效果，在各自的 `jp-style.js` 中保留 `fontFamily: 'ygo-jp'`，设置 `sideBearingRatio: 0.5`。通过 `inheritProp()` 继承这一个标量字段，并在各 `draw*()` 中明确传入，避免切语言或换字体后残留旧比例。

同时审计所有硬编码 `fontFamily: 'ygo-jp'` 的位置，保持原名，确认需要处理的文字也能取得内部比例；数字等普通 Text 使用新字体原生度量，不套留白处理。第二期 ATK/DEF 等共享 `ygo-jp` 的绘制路径也会读到替换后的字体，需要一并检查，不能以字体名未变或未启用日文样式认定它们不受影响。

Rush Duel 使用另一套日文字体，本次不自动启用；中文、英文、韩文、星界文字、自定义字体和注音字体不自动套用本规则。使用其他字体的路径保持原有度量，共享 `ygo-jp` 资源的路径按上一段单独回归。

## 7. 字体加载与缓存

复用 [现有 ready 流程](card-ready.md)，不增加第二套“字体加载完成”事件。

- 字体未加载时继续显示原来的 fallback 预览，不把新字体的留白规则用于 fallback。
- 卡片通过加载记录与布局上下文取得已加载字体及实际二进制数据。字形是否属于该字体由动态字符映射判断，不以 `document.fonts.check()` 猜测。
- 字体数据与加载使用同一个资源请求；浏览器请求允许验证同名静态文件的缓存，不为解析另发一次请求。
- 复用 `fontVersion` 触发卡片重排，但卡片各自的局部版本号不清空共享字体度量。
- 独立 `CompressText` 同时响应现有 `loadingdone` 与加载器的二进制字体完成通知，复用原来的微任务合并逻辑；销毁时移除订阅。自管字体但未提供给项目加载器的数据，先走原生路径。
- 解析结果与字符原始度量均以字体加载记录为键，使用模块级 WeakMap 共享。每个字体加载实例只解析一次、每个实际用到的字符只读取一次边界；不同 CompressText、字号、比例、后端和卡片版本均复用。
- 更换或重试产生新的字体记录，自动使用新缓存；旧记录释放后可被回收。每个 CompressText 只保存自己的正文节点、调整后宽度、位置和换行结果。
- 单次排版只解析一次字体选择，原生文字不走逐字路径；不在每次字号试探中重新解析字体或遍历全部字符。
- `ready` 仍等待字体、图片、最终排版和实际绘制；没有可靠度量时保留文字可见，不另造一个布局就绪 Promise。

## 8. 兼容性边界

本次采用统一的 50% 比例留白，汉字不再额外添加旧字体每侧的 30 单位。汉字占宽与旧版存在明确差异，换行、压缩和整体宽度需要重新检查，不能以“字形未改”为由认定排版效果完全不变。这一比例不代表官方游戏王的排版设置，也不承诺浏览器和 Skia 抗锯齿逐像素相同。

全角数字已按用户要求更换为 Leisho 3 半角字形及 702 占宽，这是明确保留的新效果。含数字文本的换行、压缩和整体宽度可能与旧字体不同，不能为了旧图一致再次把数字扩到 1024 或再压缩留白。

开发时使用 Git 基线中的旧字体度量和卡图作视觉对照，不在发布资源中保留第二份字体，不增加兼容模式或补白参数。后续对照实卡调整时，修改内部比例和经过审核的字符规则，用户配置与卡片数据不承担这些排版细节。

替换后的 `ygo-jp.woff2` 与新规则必须一起发布；`font-list.json` 不新增条目，现有加载路径保持不变。部署时同步更新同名文件及其静态缓存；库使用者若配置独立 `resourcePath`，也需要更新该目录中的字体。不能只升级代码、继续使用旧字体。构建产物只通过现有构建命令生成，不手工编辑 `dist/` 或 `docs/`。

## 9. 实现位置

实现位于下列模块：

## 10. 实施顺序

1. 保存旧版基线卡图和度量，核对交付字体指纹，直接替换 `ygo-jp.woff2`，加入 CFF / `hmtx` 与真实渲染检查。
2. 独立完成共享测量和留白公式，遍历字体覆盖的汉字、假名和额外字符，核对当前 6900 个恢复字符的历史基线及排除类别，不按固定名单限制运行时范围。
3. 增加正文段适配器，先在独立 `CompressText` 验证，再接入所有布局环节。
4. 接入两种 OCG 卡片的日文样式，补齐字体加载、切换与 `ready`。
5. 做旧版基线 / 新字体原始度量 / 新字体 50% 比例留白的 Playground 对照，重点检查汉字变窄后的换行、压缩与实卡接近程度；旧字体不进入发布资源。
6. 通过源码和发布包的浏览器、Node 验证后，再整理实现文档与变更说明。

## 11. 验收

| 场景 | 预期 |
| --- | --- |
| 字体内部度量 | 全部字形的 CFF 实际占宽与 `hmtx` 相同；不能只检查一个表 |
| 资源命名与同名替换 | 沿用 `ygo-jp.woff2`、`ygo-jp` 和原清单条目；发布包不增加字体别名或第二份旧字体，部署时同步更新资源 |
| 新字体在真实 Skia / 浏览器中 | 参考字号下已恢复字符为 1024，全角数字为 702；Leafer 与 Canvas 自然占宽一致，不假定所有 CJK 字符都等宽 |
| 字符处理范围 | 当前字体覆盖的全体汉字、假名和明确列出的额外字符按统一规则处理；新增汉字或假名不需逐个加入固定名单；fallback 字形保持原生路径 |
| 动态字体信息 | 任意登记的实际字体可按相同规则读取，覆盖不同字体名和 1000/1024 单位字体；无需预写指纹、覆盖或字宽 |
| 日文内部比例 0.5 | 处理范围内的字符符合统一比例公式并按设计单位逐侧取整；已核对的 6900 个恢复字符中，6725 个汉字较旧字体少 60 单位占宽，其余 175 个恢复字符保持旧度量 |
| 排除类别 | 拉丁、希腊、西里尔、全角数字、全角字母和未明确列出的标点不调整留白 |
| `々〆゛゜ゝゞー` | 按明确集合处理，不能因 Common 分类漏掉，也不能扩大到整个标点区块 |
| 长音符 `ー` | `コーヒー`、`スーパー` 和连续 `ーー` 按同一比例缩减当前字体的留白，字形不变，绘制位置与换行宽度一致；比例为 1 时保留原始度量 |
| 内部比例 0 / 0.5 / 1，缺省与无效值 | 只改变留白；字形无变形，宽度为正有限值；比例 1、缺省或无效值回到原生路径 |
| 对外配置与保存数据 | 不新增用户可配置字段、公共参数类型或卡片 JSON 字段；内部比例随日文样式生效 |
| 字距与空格 | 字距计入一次，保留当前末字字距约定；连续空格不变成零宽，全角空格保持原度量 |
| 换行、首行压缩、两端对齐 | 采用调整后的占宽，行首/行末无重复偏移；显式空行和尾部处理约定不变 |
| `fontScale`、小字、Group 缩放、导出倍率 | 不累计缩放，布局与绘制一致；#32 的边界修复不回归 |
| ruby、粗体、描边、渐变 | 正文与注音位置一致；样式传递到内部字形，渐变坐标不因拆字重置 |
| 字体延迟与失败 | fallback 可见；加载后只按现有机制重排；失败语义沿用资源流程 |
| 切语言、字体、文本和配置 | 无旧测量、旧节点或旧配置残留；销毁后不继续重排 |
| 共享 `ygo-jp` 的绘制路径 | 第二期 ATK/DEF 等使用新字体后，文字比例传递正确，数字仍使用原生度量；覆盖日文与其他实际共享该资源的语言 |
| 混合文字与字素簇 | 未处理文字保留原生段，组合符号、IVS 等不拆坏 |
| 性能 | 断言首次遇到字符才读取其边界；跨实例、字号、比例及卡片版本共用缓存；未启用时不解析字形，保留原有路径 |
| 发布包 | `.tgz` 独立消费项目中的浏览器和 Node 都使用发布产物，并能完成 ready 与 PNG 导出 |

实现后执行相关测试、修改文件 ESLint、`pnpm test`、`pnpm build:lib`。修改 Playground 后构建网站并在外部 Edge 验证。PNG 对比限定同一后端；分别核对统一比例下的汉字变窄、假名与标记保留原有度量，以及全角数字的新字形和占宽，不以整卡必须复现旧图作为验收条件。

## 12. 已确认的设计决策

1. 只保留内部 `sideBearingRatio`，日文样式设为 0.5；不额外补白，接受汉字较旧字体变窄并据实卡校准的效果。
2. 直接替换原 `ygo-jp.woff2`，不改文件名、注册名或清单；新字体与排版代码同步发布，旧版仅通过 Git 基线作开发对照。
3. 处理全体汉字、假名及明确列出的额外字符，结合当前字体覆盖判断；6900 仅为本版恢复字符的基线统计，不作为范围限制。
4. 从实际字体动态读取单位、覆盖和字形度量，不预生成 `font-profiles`，不绑定特定字体名；只读取用到的字符并跨实例共享缓存。
