# 文本断行规则细化

本次以当前 PR 中的 `dd15fac9a8a956ad535c3f8293f78fe640093b02` 为对照，修正分词边界和超宽回退规则。此前性能优化使用的对照版本不变；这里记录后续规则细化允许产生的排版差异。

## 依赖选择

继续使用 `css-line-break@2.1.0`，不增加或替换项目依赖。它提供普通断行和 strict/break-all 应急断行，项目层负责 ruby、富文本及字素完整性。

该库的数据来自 Unicode 13，不能据此声称支持所有最新 Unicode 断行规则。不过，保留的汉字预留区间已涵盖部分后续新增汉字；数据旧不等于所有新汉字都会分错。用于评估的 99 组现有文本，在字素保护后，与较新实现的断点一致，暂未发现值得承担全量排版变化的换库收益。

`Intl.Segmenter` 用于过滤字素内部断点，保护浊点、IVS、emoji 组合。它不能补齐全部新版 UAX #14 规则，其 Unicode 版本也跟随浏览器或 Node 运行时。以后出现实际文本无法正确断行、需要大范围自维护规则，或更换库有明确收益时，再重新评估。

参考：[css-line-break 数据](https://github.com/niklasvh/css-line-break/blob/master/src/LineBreak.txt)、[Unicode 更新请求](https://github.com/niklasvh/css-line-break/issues/32)。

## 实现

1. 解析原文，得到正文、注音、粗体状态和原文范围。用对象保存 ruby，不向字符串写入 `__RB0__` 等占位符。
2. 连接实际正文，调用 `LineBreaker` 获得断点，并将其码点坐标转换为 UTF-16 坐标。
3. 过滤落在 ruby 或字素内部的断点。`[正文(注音)]` 是原子单元，空注音 `[正文()]` 也按相同语法处理。
4. 将绘制需要独立测量的空格、固定符号和零宽控制符保留为独立项，但不因此额外开放换行。粗体开关同样不创建断点。
5. 纯文本超宽时保留原来的二分测宽，再将切点调整到 strict/break-all 和字素规则共同允许的位置。跨多个绘制项时也检查组合后的边界，防止 ruby 后的句号、NBSP 等在回退中失去约束。

简单 ASCII 单词沿用所有字符边界均可应急断行的快速路径，避免为原有长英文场景重复构造断点集合。解析缓存仍只保存当前实例当前文本的不可变内容；测量、布局和节点不共享。

原有 `splitBreakWord` 和 `splitBreakWordWithBracket` 保留原文，可通过拼接结果还原输入。供排版使用的 `parseBreakText` 统一 CRLF、CR、NEL、LS、PS、FF、VT 为 LF，并保留原有裁去末尾空白的行为。

原文中的 ZWSP（U+200B）和 WJ（U+2060）不再删除，独立项宽度为零且不绘制。它们仍参与断点判断。

## 保持不变

- `CompressText extends Group`、公开参数与 Card 接口。
- 全局行高、各卡片样式、y 坐标和字体度量方式。
- 正文与注音的缩放算法、小字切换和高度压缩精度。
- `ready`、字体加载失效、图片引用和批量复用流程。
- 带非空注音的长 ruby 保持完整，不通过拆开正文解决超宽。

当不可拆单元本身比容器宽时，保留完整单元，可能溢出容器；不额外引入缩放策略。例如极窄容器中的“甲。”和超长 ruby。显式换行后的标点按输入保留，不跨硬换行向上一行移动。

## 可观察的前后差异

以下示例固定字号 20、日文字体、留白比例 1、左对齐；NBSP 示例使用英文字体。`/` 表示换行，具体断行受字体和容器宽度影响。

| 输入与条件 | 改动前 | 改动后 |
| --- | --- | --- |
| `__RB0__ [日(にち)]` | 原文字串被占位符替换，显示成“日 日” | 保留“__RB0__ 日” |
| `前前A[日(x)]B`，宽 80 | `前前 / A日B` | `前前A日 / B`，与未注音正文一致 |
| `X 100\u00A0ATK`，宽 75 | `X 100 / ATK` | `X / 100 ATK`，NBSP 两侧不直接断开 |
| `前甲 ，乙`，宽 48 | `前甲 / ，乙` | `前 / 甲 ， / 乙`，逗号不出现在自动换行的行首 |
| `甲。乙。`，宽 25 | `甲 / 。 / 乙 / 。` | `甲。 / 乙。`；每行宽 30，保留标点归属 |
| `[这是一段很长的文本()]。`，宽 100 | 空注音正文拆成两行 | 正文与句号完整保留，宽 190，会溢出 |
| `甲\r\n乙` | 换行，但第一行残留 CR 测量宽度 | 与 LF 完全相同；左对齐示例像素不变，居中、右对齐可能受修正后的行宽影响 |
| `甲\u2028乙` | 一行 | 两行，与 LF 相同 |
| `[①甲(いち)]乙` | 固定符号提前切开了 ruby 语法，显示原始标记 | 正确显示“①甲乙”及注音 |
| `甲\u200B乙[日(にち)]` | 原文 ZWSP 被删除 | 原文控制符保留、零宽隐藏；该示例的像素不变 |

上述 15 组边界用例中，10 组布局快照变化，其中 8 组导出像素变化；其余用例包括非空长 ruby、字素组合和部分粗体/拉丁文场景，保持原结果。这个统计只针对固定用例，不是对任意输入的兼容性保证。

## 验证与性能

- Node 原生测试覆盖实际 Skia 测量与换行、ruby 完整性、标点回退、NBSP、换行符、零宽控制符、原文字串碰撞、字素完整性，以及普通/小字试排和实例复用。
- 对照快照覆盖原有 99 组文本、100 个连续更新状态、同一实例连续导出 100 张完整卡片和五种卡片类型。比较节点布局与导出 RGBA，而不是仅比较文本内容。
- 新增 15 组边界文本；数值试排与完整试排在这 114 组文本上对照。
- 冻结对照来自 `git archive dd15fac`，在缓存目录运行，不建立 worktree、不切换分支。
- 发布包验证使用 `pnpm build:lib` 产物打包后安装到独立消费项目，核对已安装文件与 dist 的哈希，再对照源码的布局及像素。

本轮实际结果：156 项测试通过，修改的 JavaScript 文件通过 ESLint，库构建成功；Node 的原有 99 组文本、100 个更新状态、100 张连续导出和五类卡片与冻结版本一致。独立消费项目中的发布包在全部 114 组文本及同一批更新、导出、卡片类型上与源码完全一致。

浏览器复核已在外部 Edge 中完成，分别使用独立页面运行冻结版本、当前源码和独立消费项目安装的发布包。原有 99 组文本、100 个更新状态、100 张连续导出及五类卡片的节点布局和 RGBA 哈希完全一致。15 组边界用例中，仍是上述 10 组布局变化、8 组像素变化，与 Node 对照一致。发布包在全部 114 组文本及全部更新、导出、卡片类型上与源码完全一致，测试未收集到未处理的 Promise 拒绝。

复核中修正了本地验证缓存：同一路径、同一版本的 tgz 被重新打包后，Vite 为 `node_modules` 返回的 immutable HTTP 缓存可能让浏览器继续加载旧文件。验证服务现在每次启动强制重新预构建依赖，运行时入口附带时间戳。重新打包和安装本地 tgz 后，应重启验证服务再运行三组对照。发布包模式的预构建入口也已核实来自独立消费项目的已安装产物。

同机顺序运行基准，长英文构造中位数由 8.41 ms 到 8.36 ms，长 CJK 由 12.13 ms 到 12.05 ms，普通内容更新由 2.60 ms 到 2.58 ms，宽度更新由 2.59 ms 到 2.67 ms。这些差异不足以说明整体提速；本次重点是正确性，常规场景的中位数基本保持，内容更新的 P95 没有改善。
