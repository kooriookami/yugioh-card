# 横排行首行尾标点挤压

已实施。排版对照版本为 `master` 的 `305138a`。

## 1. 排版规则

- 只处理横排视觉行的外缘。自动折行、显式换行和单行栏位都使用同一规则。全角标点在行首收左侧留白，在行末收右侧留白，独占一行时可同时收两侧。行中的标点按原有间距排版。
- 仅 `language: 'jp'` 的卡片启用挤压，字体预设不参与判断。常见全角标点、弯引号和中点查共用表，Unicode 明确定义的全角标点和符号按码位与字符类别识别。汉字、假名、字母、数字和 ASCII 标点按原规则排版。字体中的实际留白用于计算挤量。
- 保留的显式空格仍占行缘位置。判断行尾时跳过现有规则已经清理的尾部空格，以及不绘制的零宽控制符。连续标点碰到行缘时，只收紧贴行缘的那个符号的外侧留白。两个标点之间仍按原规则排版。
- 断点继续由现有行首行尾禁则给出。比如自动换行时，`。` 随前文，`【` 随后文。挤压参与选择断点，ruby 正文与注音仍作为一组。标点的字形按本行字号和横向倍率绘制。

中日文排版资料可用于参考标点分类和行缘处理，卡片的具体对齐位置以同版式实卡校准。 [W3C 中文排版需求 §6.1.1、§6.3.2.3](https://www.w3.org/TR/clreq/) · [W3C 日文排版需求 §3.1.5](https://www.w3.org/TR/jlreq/#positioning_of_opening_brackets_at_line_head) · [§3.1.9](https://www.w3.org/TR/jlreq/#positioning_of_closing_brackets_full_stops_commas_and_middle_dots_at_line_end)

## 2. 度量与断行

复用 [字体解析](../packages/src/utils/font-info.ts) 和 [字形度量](../packages/src/compress-text/glyph-metrics.ts)。以实际加载的字体为单位，按需缓存用到的标点。字体未加载、字形缺失或无法确认度量时先用自然占宽，字体就绪后走现有重排流程。标点度量独立于 `sideBearingMode`，使用 `native` 的文本也能启用。

设字形原始占宽为 `A`，字形边界为 `minX` 和 `maxX`。左侧可用留白来自 `minX`，右侧来自 `A - maxX`，乘以实际字号与该字的横向倍率并换算为像素。挤量以正留白为上限，给描边和可能伸到行缘的注音留出实际空间。若测宽已计入最后一个标点之后的额外字距，该字距也属于行尾外侧空间。字形绘制沿用整段原有的 `Text` 或 `BodyRun`。

| 当前字体和标点 | 自然占宽 | 可用于行缘对齐的字体留白 |
| --- | --- | --- |
| `ygo-jp` 的 `【` | `0.5em` | 左侧约 `0.226em` |
| `ygo-jp` 的 `。` | `0.5em` | 右侧约 `0.232em` |
| `ygo-jp` 的 `】` | `0.5em` | 右侧约 `0.233em` |

换行时累计自然占宽，取候选行的首末标点各算一次挤量。

```text
候选行有效宽度 = 候选行自然占宽 − 行首挤量 − 行末挤量
```

例如试排 `甲。` 时可计入 `。` 的行尾挤量，再试排 `甲。乙` 时，`。` 回到行中，按自然占宽计入。若 `甲。` 放得下而 `甲。乙` 放不下，就在句号后换行。若 `甲。` 也放不下，再找更早的合法断点或进入现有超宽回退。行确定后，行首挤量用于绘制起点，行尾挤量用于行宽。左齐、居中、右齐和两端对齐都以有效行宽为准。两端对齐继续按现有规则分配剩余宽度，所以换行或剩余宽度变化时，字缝会随之调整。

[最终布局](../packages/src/compress-text/compress-text.ts) 和 [高度试算](../packages/src/compress-text/layout/trial-layout.ts) 共用上述行宽规则，超宽回退、指定段压成一行和小字重排也用同一度量。每次接纳断行单元时更新累计宽度及首末项，避免反复扫描整行。注音沿用原先的正文锚点、拉开字距和最小缩放规则。

## 3. 卡片接入

日文样式顶层设置 `punctuationTrim: true`，各栏位通过 `inheritProp` 继承，也可显式设为 `false`。卡片读取语言样式中对应栏位的布尔值，并为 `CompressText` 选择挤压方向。正文、灵摆效果和种族类型行使用 `'both'`，魔陷类型栏的左段和右括号分别使用 `'start'`、`'end'`。

| 卡片类型 | 栏位 |
| --- | --- |
| OCG | 效果正文、灵摆效果、种族类型、魔陷类型 |
| 游戏王第 2 期、超速决斗 | 效果正文、种族类型、魔陷类型 |

### 种族类型行

标点挤压上线时，从样式类型和各样式表中删除 `textIndent`，同时删除 OCG、第 2 期和超速决斗绘制种族类型行时对该参数的读取。三种卡片分别以正文区域原有的 `x = 109`、`149`、`99` 为左锚点。日文全角 `【` 的挤量由排版引擎按实际字形留白计算，其他语言从左锚点按字体自然留白排版。 [样式类型](../packages/src/card/style-types.ts) · [OCG 类型行定位](../packages/src/yugioh-card/index.ts) · [第 2 期类型行定位](../packages/src/yugioh-series-2-card/index.ts) · [超速决斗类型行定位](../packages/src/rush-duel-card/index.ts)

以能完整排在一行且无描边、无横向缩放的 OCG 为例，日文 46px 的 `【` 左留白约 10.4px，旧坐标偏移为 9.2px，改用实际留白后，左括号字面预计比旧版左移约 1.2px。英语、韩语的 `custom1` 和 `custom2` 使用半角 `[]`，移除旧偏移后，整行预计分别右移 18.4px 和 17.6px。验收时以实际左边距和实卡叠图核对这些变化。

### 魔陷类型栏

把 `【陷阱卡 + 类型图标 + 】` 视为一行。现有实现将它分成左侧文本、可选图标和右括号三个节点。左侧文本只收整栏最左侧的留白，末尾的 `】` 只收右侧留白。因此右括号靠图标的一侧、类型文字与图标的间距，以及有无图标时的拼接方式都按现有样式计算。

- **OCG 和第 2 期**从右向左定位。各语言和字体预设用 `right` 设置距卡片右边缘的距离，再用右括号的有效宽度计算起点，依次定位图标和左侧文本。OCG 日文默认样式以卡图框右缘 `x = 1245` 对齐收紧后的 `】`。简中、繁中和星界的默认 `right` 分别为 `134px`、`138px`、`144px`。OCG 的 `custom1` 和 `custom2` 在所有语言下都用 `149px`。第 2 期按原字面位置将全角右锚点设在 `x = 1220`。
- **超速决斗**从左向右定位。先处理 `【` 的左侧，再按有效宽度摆放图标和 `】`。魔法、陷阱以及有图标和无图标的分支都用整栏的外缘来判断。

代码位置见 [OCG 魔陷类型](../packages/src/yugioh-card/index.ts)、[第 2 期魔陷类型](../packages/src/yugioh-series-2-card/index.ts)、[超速决斗魔陷类型](../packages/src/rush-duel-card/index.ts)。

## 4. 验收

- 在临界宽度下比较 `甲。乙`、`甲【乙】丙`、`[甲(こう)]。`。覆盖行首、行末、行中、显式换行、单行标点以及有显式空格的情况。核对字形、换行和最终占宽，确认段压缩试算与最终行数一致。
- 用之前已经叠图对齐的日文种族类型行复核左括号，另外对照第 2 期和自定义预设。切换卡片语言并检查正文、灵摆效果、类型行和魔陷标签的行缘留白。用右对齐的日文陷阱类型栏复核 `】`。魔陷样例分别覆盖通常魔法或陷阱、带图标的魔法或陷阱，量出括号字面到版面边缘的距离和图标左右间距。
- 在 Edge 和 Node/Skia 使用同一字体比较布局坐标。覆盖首次字体加载、缩放、长注音和连续导出。以同一后端的改动前后图核对无行缘标点的样例与行中标点间距，并记录栏位位置和换行发生变化的样例。

## 5. 验证结果

- `pnpm test` 共 186 项通过，`pnpm build:lib` 成功。回归用例覆盖行首行末、行中恢复占宽、行尾空格、对齐、段压缩、小字、长注音、三类卡片的魔陷栏、同一实例切换语言时启停挤压，以及栏位显式覆盖继承值。 [回归测试](../packages/src/compress-text/__tests__/line-punctuation.test.js)
- 初版在 Edge 分别加载源码和构建产物，复核了字体加载前后的定位、魔陷图标间距和 PNG 导出，并用 Node/Skia 的构建产物连续导出了 100 张卡片。
- Node/Skia 对照 `305138a`，没有行缘全角标点的简中、繁中、日文和英文样例像素一致。日文陷阱栏的 `】` 在参考截图和本次导出中均比卡图框右缘内收 1px。
